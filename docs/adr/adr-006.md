# ADR-006　分阶段独立进程的评测架构

## 背景
评测执行环境为 1 vCPU、约 1.5 GB 可用物理内存、3.6 GB Swap 的云主机。
bge-m3 与 bge-reranker-v2-m3 的 fp32 权重各约 2.2 GB。

## 决策
评测拆分为 bm25 / small / hybrid / m3 / rerank / merge 六个阶段，
每阶段为独立进程，中间排名以 `.npy` 落盘，最终由 merge 阶段汇总。

## 理由
单进程内连续加载两个 2.2 GB 模型将超出可用内存，触发 OOM。
Python 进程内 `del` 与 `gc.collect()` 不保证将内存归还操作系统，
只有进程退出才能完整释放。分阶段架构同时带来两项工程收益：
任一阶段失败可单独重跑而不必重算全部；各阶段峰值内存可独立测量并归因。

## 后果
阶段间需通过磁盘交换中间结果，引入少量 I/O 开销（排名矩阵为 100×200 int32，可忽略）。
`hybrid` 与 `rerank` 阶段依赖前序阶段的落盘产物，执行顺序不可调换。
